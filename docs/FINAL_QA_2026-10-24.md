## Fixed defects and scope

1. **Readable files incorrectly unavailable.** `VideoProbe.colorInfo` and
   `AVCanonicalMediaStateAdapterV4.colorState` rejected omitted color tags;
   changing only the picker would leave export planning rejected. The shared
   `VideoDecodedColorResolver` now reads the decoder's actual first-frame color
   attachments for omitted fields in a single stable format description. It
   retains explicit declarations and strict changing-format checks. Untagged
   test H.264 resolves to SMPTE-C / 709 transfer / 601 matrix, so assuming every
   source is BT.709 would alter color. The writer contract preserves resolved
   SDR tags and verifies them after reopening.
2. **ProRes 422 rejected.** Core Media advertises a 12-bit decoding descriptor
   for the 10-bit ProRes 422 signal. The probe reports signal precision and the
   whole-asset planner accepts the four named ProRes 422 variants through its
   explicit 10-bit P010 4:2:0 processing conversion. This is not preservation
   of original 4:2:2 chroma sampling. Missing chroma location remains unknown;
   no unsupported siting default was invented.
3. **Unhelpful error 11.** `DeterministicV4MediaSegmentError.writerRejectedTrack`
   has stable domain/code 11 at two `AVAssetWriter.canAdd` refusal sites. It now
   supplies an actionable description and journals codec, raster, writer state,
   and settings applicability. A preceding 60-configuration probe did not
   reproduce refusal. A bare number cannot distinguish this error from code 11
   in another domain; the customer's exact cause remains unknown.
4. **Completed-job Compare used a deleted source.** Native UI reproduced this.
   Completion exposed a private source snapshot removed by terminal cleanup.
   `MirmirViewModel` now retains the selected original and security-scoped
   leases, including same-session pause/resume; the workspace consumes that
   URL. A recovered job without retained access uses the independent picker.
   A regression failed before the fix; the fixed state test and real export
   into actual comparison players pass. Workflow serialization is unchanged.
5. **Stale verification bindings.** Reviewed changed capture observers and
   recovery producers, rebuilt P06 twice, refreshed matching contract pins and
   aggregate trust descriptor. Historical hot-path replay runs the exact
   pinned original evaluator against original-source identities, including its
   strict hash checks. A tampered historical capture is still rejected. Old
   captures do not qualify the new runtime. New runtime identity can make older
   checkpoints incompatible; existing compatibility checks remain fail-closed.
6. **Opt-in capture ordinal bug.** The legacy-named
   `testCaptureV3BaselineWhenRequested` kept one frame counter across newly
   prepared engines. The second route started at 25 although the engine
   requires 0. The counter now belongs to each prepared route. The production
   ordinal invariant and all assertions remain intact. Current captures do not
   replace historical v3 baseline evidence.

7. **Arrival-sensitive H.264 encoding.** The verified x86-64 run failed strict
   decoded parity for 66, 156, and 157 frames, with respectively 24, 100, and 100
   different decoded frames despite identical traced pre-encoder pixels and
   timing. A writer-only control using the same decoded input and timestamps
   changed only delivery pacing (fast versus 40 ms pauses): automatic H.264
   reordering changed B/P choices and 61 of 66 decoded frames. With reordering
   disabled, both control outputs matched. Apple's
   [frame-reordering setting](https://developer.apple.com/documentation/avfoundation/avvideoallowframereorderingkey)
   leaves that choice to the encoder by default. `VideoWriterFormatContractV4`
   now disables it for deterministic H.264 only. The new 192×128 pacing
   regression fails before the change and passes in all final suites; the
   existing three CPU/Metal cases also pass. HEVC/ProRes policy and strict
   decoded-frame assertions are unchanged. This changes compression efficiency:
   the standalone control was 54355 bytes without reordering versus 49499 bytes
   for its fast default encode; that one fixture is not a general size estimate.
   Original failure traces and movies remain in `rosetta-parity-attachments/`;
   controls and comparisons are `encoder-arrival-control-*` and
   `encoder-pacing-before-192.xcresult`. Historical October 7 evidence is retained
   without alteration; current reproduction and repair are separate evidence.
8. **Smooth Motion test assumed hardware support from OS version.** The x86-64
   API reports unsupported hardware and no geometry limit. The test now asserts
   the app's explicit API-unavailable result on unsupported hardware, while
   retaining the exact geometry-limit assertion on supported hardware. This
   corrects the test contract; the production availability checks are unchanged.

## Commands

The full suites use `xcodebuild test -project <internal-copy>/Mirmir.xcodeproj
-scheme Mirmir -configuration Debug|Release -destination platform=macOS,arch=arm64
-parallel-testing-enabled NO`, distinct `PRODUCT_BUNDLE_IDENTIFIER` values and
Derived Data/result paths. Release tests additionally use `ENABLE_TESTABILITY=YES`.
Complete invocations are the first lines of each build log.

Production build: `xcodebuild -project Mirmir.xcodeproj -scheme Mirmir
-configuration Release -destination generic/platform=macOS
ARCHS="arm64 x86_64" ONLY_ACTIVE_ARCH=NO build`, followed by
`codesign --verify --deep --strict` and `lipo -archs`.

Opt-ins use `xcodebuild test-without-building -xctestrun <QA-plan>` with their
explicit environment keys. Python commands are listed individually in
`python-encoder-fixed.json`. Identity/version checks:
`python3 script/v4/repository_identity_v4.py --repository .`,
`python3 script/update_version.py --check`, and
`python3 script/v4/update_roadmap_tracker.py --check`.
