## Found and fixed

| Observed failure | Verified cause and change |
| --- | --- |
| Successful conventional export silently lost alternate video, subtitles/captions, title and other rich-asset lanes. The disabled first video could be processed instead of the selected enabled video. | `VideoProcessingSession` previously wrote a selected video/audio-only movie and validated raster/audio. It now encodes the first enabled primary into a temporary artifact, then uses the existing whole-asset planner/executor to migrate retained lanes, groups, associations, chapters and metadata. Audio omission uses the same explicit policy as the deterministic route. Four original regressions failed before this change. |
| Stored B-frame duration and edit-map loss. | Native movie-view reader timestamps already apply edits and can repeat/omit stored samples. The executor reads pass-through movie video media tables once, skips payload-free video control buffers and restores the original edits. Independent stored `stts`/`ctts`/sizes, packets, timing and PCM remain checked. The two stored-timing regressions failed before this change. |
| Selected primary with internal/repeated/trimmed/scaled edits could not export. | The existing replacement contract intentionally allows only a single unscaled edit, optionally with a leading empty interval. The new conventional branch instead encodes the complete source media normalized onto zero, authenticates its declared full range against the original, restores original edits and verifies the replacement in the full-media domain. Legacy deterministic replacement guards remain. The internal-edit regression first failed with `replacement_requires_authorized_media_mapping`. Seven moving-primary variants now check actual scaler-input frame order/timestamps, stored clocks and final edits under both audio policies. |
| Cancellation requested at publication still overwrote an existing destination. | Publication progress could synchronously cancel after the last token check; the conventional wrapper also polled an unrelated token. The migration token now checks its upstream cancellation synchronously, and publication rechecks after its callback. Both destination-sentinel regressions failed before repair and now pass. |
| Wider testing exposed an original-AVI regression in the new media-table path. | `AVMovie` supports QuickTime/ISO containers; original AVI cannot supply those movie edits. The observed AVI native identity mapping uses the original reader only after content-signature and exact zero-origin identity-edit checks. Resolved AVI-derived MOV still uses strict movie-table handling. The existing AVI preservation regression and new MPEG4/H264 AVI conventional workflows pass. |
| Wider testing exposed an interpolation tail failure: movie duration `1/10`, stored media only `1/12`. | Native encoder controls locate the shortening in the first encode; remux retains all five real packets exactly. H.264/HEVC require both explicit frame durations and disabled reordering to retain the longer terminal hold. Only temporal output uses that policy and a one-frame lookahead; ordinary spatial adaptor encoding is unchanged. Real VT interpolation and CPU timing-proxy regressions for H.264/HEVC/ProRes pass. This changes temporal bitstream structure/compression behavior; no file-size/performance improvement is claimed. |
